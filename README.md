**Batuhan Dağcı | 34059**

## Research Question

Do I loop music more during exam periods compared to regular days?

**Metric:** Daily loop ratio = proportion of plays on a given day that repeat a track already heard that same day.

## Hypothesis

- **H₀:** Loop ratio during exam days = loop ratio during regular days
- **H₁:** Loop ratio during exam days > loop ratio during regular days

## Dataset

Personal Spotify streaming history enriched with period labels (`regular`, `pre_exam`, `exam_day`) and audio-feature proxies. Located at `data/streaming_clean.csv`.

## ML Results

### Scope Note: Behavioural Features Only

The research question — *"Do I loop music more during exam periods?"* — is a behavioural-repetition question. The hypothesis test (`eda.ipynb`) targets `loop_ratio` exclusively. To keep the ML pipeline aligned with this scope, the feature set is restricted to behavioural signals: repetition, listening volume, and timing. Audio-feature proxies (`valence_proxy`, `energy_proxy`) and Last.fm mood tags were excluded from the model — they belong to a different research question (mood shift) that the available data does not support, and including them would dilute the loop-focused analysis.

### Time Window

The original proposal scoped the analysis to the Fall 2025 semester. We use September 15, 2025 – January 31, 2026, covering the academic period from start of classes through the final exam window. This excludes summer/break periods where "regular" days reflect absence of school rather than absence of exam stress, making the regular vs exam comparison more meaningful. The narrower window also produces a less degenerate class balance (regular: 104 days, exam_period: 34 days) for ML modeling.

### Problem Setup

We frame the ML task as classification of a day's `period` from its aggregated listening behaviour. Due to severe class imbalance (regular: 104 days, pre_exam: 24, exam_day: 10), we run two parallel setups:

- **Binary (primary):** `exam_period` (pre_exam + exam_day) vs `regular`
- **3-class (secondary):** original labels, illustrative only

See `ml.ipynb` for the full pipeline (feature engineering → CV → test evaluation → permutation importance).

### Best Model Test Performance

- **Binary setup:** Logistic Regression — F1: 0.526, ROC-AUC: 0.701, Avg Precision: 0.576
- **3-class setup:** Logistic Regression — F1-macro: 0.333, ROC-AUC (OvR): 0.506. **Below the Dummy baseline (CV F1-macro: 0.369), and ROC-AUC near 0.500 indicates near-random ranking on test.** With only 2 exam_day samples in the test set, this setup is statistically underpowered. The 3-class results should be read as evidence that finer-grained classification is not feasible at this sample size — not as a working classifier.

### Top Features (Permutation Importance, Binary Setup)

- `unique_artists`: 0.1655 ± 0.0705
- `total_listening_minutes`: 0.1271 ± 0.0654
- `loop_ratio`: 0.1262 ± 0.0479
- `tracks_per_play`: 0.1262 ± 0.0479
- `unique_tracks`: 0.0927 ± 0.0799

This ranking shows which behavioural features most influence the binary classifier's predictions. `loop_ratio` ranks 3rd, tied with `tracks_per_play`. The tie is not a coincidence: by construction, `tracks_per_play = unique_tracks / total_plays = 1 - loop_ratio`, so the two features are perfectly anti-correlated and carry identical information from the model's perspective. Permuting either one degrades F1 by the same amount because the other can fully recover the signal — they should be read as a single repetition feature ranking 3rd overall, behind `unique_artists` and `total_listening_minutes`. The hypothesis-motivated repetition signal is therefore clearly present in the model, though `unique_artists` (artist diversity) carries the strongest unique behavioural signal for distinguishing exam periods.

### Limitations

**Sample size and signal.** The dataset covers a single user over one semester (138 daily observations, 34 exam-period days, 10 exam days). Binary classification shows a clear signal: Logistic Regression reaches CV ROC-AUC 0.708 and test ROC-AUC 0.701, well above the Dummy baseline (0.500), with test F1 0.526 vs Dummy CV F1 0.209. The 3-class setup, by contrast, fails to beat the Dummy on test, indicating insufficient data to separate `pre_exam` from `exam_day`. Single-semester, single-user results are not generalizable to other students or semesters.

**Loop ratio as a metric.** The "loop" definition counts any same-day repeat as a loop, regardless of how many times a track is replayed. Alternative definitions (e.g., requiring 3+ plays, or weighting by inter-play gap) could yield different conclusions. The metric also conflates active replaying with passive playlist looping.

**Temporal labelling.** The `pre_exam` label assigns the 3 days before each `exam_day` to the same class. Exam sessions cluster in specific weeks, so calendar-position features (`day_of_week_num`, `is_weekend`) may act as proxies rather than capturing true behavioural change.
